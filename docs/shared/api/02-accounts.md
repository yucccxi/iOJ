# 2. 账号

> 返回目录：[iOJ 前端接口文档（v1）](README.md)

> **部署开关**：2.1 / 2.2 / 2.5 / 2.6 的邮箱验证码流程只在服务端启用邮箱验证时生效。若部署关闭了该功能：
>
> - `POST /auth/email-codes`、`POST /auth/password-reset-codes`、`POST /auth/password-resets` 返回 `400` / `1000`「邮箱验证功能未启用」
> - `POST /auth/register` **不再需要 `emailCode`**，可以直接注册

## 2.1 发送邮箱验证码

`POST /auth/email-codes` ｜ 公开

注册前先给邮箱发一个 6 位验证码。**验证码只发到邮件里，不会出现在响应中**；有效期、冷却时间与每小时上限都由服务端配置，响应如实返回，前端用它做倒计时。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `email` | string | 是 | 要验证的邮箱，≤128 字符；服务端会去掉首尾空格并转成小写 |

```json
{ "email": "alice@example.com" }
```

**响应 `data`**

```json
{ "expiresInSeconds": 600, "resendAfterSeconds": 60 }
```

| 字段 | 说明 |
| --- | --- |
| `expiresInSeconds` | 验证码有效期（秒），默认 600（10 分钟） |
| `resendAfterSeconds` | 还要等多少秒才能再发一次，默认 60；按钮倒计时直接用这个值 |

**常见错误**：`1000`（部署关闭了邮箱验证，接口不可用）、`1001`（邮箱为空或格式不对）、`2003`（该邮箱已注册，直接去登录；这也会暴露邮箱存在，属于明确的产品选择）、`2008`（发送过于频繁，`message` 会区分“冷却中”和“超出一小时上限”）、`2009`（邮件服务发送失败，稍后重试）。

> 服务端默认限制：同一邮箱 **60 秒**内只能发一次、**每小时最多 5 次**；验证码 **10 分钟**有效、最多输错 **5 次**（第 5 次输错即作废，之后即使输对也要重新获取）。这些都是部署配置项，前端不要写死。

## 2.2 注册

`POST /auth/register` ｜ 公开

创建一个普通用户账号。**启用邮箱验证时，注册前必须先调用 2.1 拿到验证码，并在请求里带上它**；完全不传 `emailCode` 返回 `2007`。关闭邮箱验证时不需要验证码，注册成功不会返回令牌，需要再调用登录接口。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `username` | string | 是 | 登录名，3-32 位字母/数字/下划线，全局唯一，注册后不可修改 |
| `email` | string | 是 | 邮箱，≤128 字符，全局唯一，也可以用邮箱登录；会去掉首尾空格并转小写 |
| `password` | string | 是 | 8-64 位 |
| `nickname` | string | 否 | 展示昵称，≤32 字；不传或传空白时默认用 `username` |
| `emailCode` | string | 启用邮箱验证时是 | 2.1 发送到该邮箱的 6 位验证码；部署关闭邮箱验证时可以省略 |

```json
{
  "username": "alice",
  "email": "alice@example.com",
  "password": "password123",
  "nickname": "Alice",
  "emailCode": "482915"
}
```

**响应 `data`**

```json
{
  "id": 12,
  "username": "alice",
  "nickname": "Alice",
  "role": "USER",
  "createdAt": "2026-10-30T11:18:05"
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | 用户 id，用于个人主页、按用户筛提交等 |
| `username` | 登录名 |
| `nickname` | 展示名 |
| `role` | 注册固定为 `USER`（管理员角色只能由后台调整） |
| `createdAt` | 注册时间 |

**常见错误**：

| code | 场景 |
| --- | --- |
| `1001` | 字段不合法；`emailCode` 传了空字符串或非 6 位数字时也走这里 |
| `2002` | 用户名已存在 |
| `2003` | 邮箱已注册 |
| `2007` | 验证码完全不传、错误、已过期、已被使用或输错次数超限；`message` 会说明具体原因，看到它就让用户重新获取验证码 |
| `1005` | 并发提交同一用户名/邮箱时由唯一索引兜底（正常预检查仍优先返回 `2002/2003`） |

> `2002` / `2003` 会明确告知用户名或邮箱是否已存在，这是与 2.5 一致的产品选择；不要把它当成“账号一定可用”的承诺，唯一性以最终插入结果为准。

## 2.3 登录

`POST /auth/login` ｜ 公开

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `account` | string | 是 | 用户名或邮箱，二选一都可以；≤128 字符。服务端不会 trim 或转换大小写：注册时邮箱已统一转小写，请使用小写邮箱登录；用户名按注册时原样提交，首尾空格会导致登录失败 |
| `password` | string | 是 | 登录密码，≤64 字符 |

```json
{ "account": "alice", "password": "password123" }
```

**响应 `data`**

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9.eyJpc3MiOiJpT0ki...",
  "tokenType": "Bearer",
  "expiresIn": 604800,
  "user": {
    "id": 12, "username": "alice", "nickname": "Alice",
    "role": "USER", "createdAt": "2026-10-30T11:18:05"
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `token` | 访问令牌，之后放到请求头 `Authorization: Bearer <token>` |
| `tokenType` | 固定为 `Bearer` |
| `expiresIn` | 有效期（秒），默认 604800 秒（7 天） |
| `user` | 登录用户信息，可直接用于渲染导航栏 |

建议前端保存 `token` 与 `user`；`user.role` 用于决定是否显示后台入口。

**常见错误**：`2005`（账号不存在或密码错误，不区分具体原因）、`2004`（账号已被禁用，**仅在密码正确时返回**；密码错误仍返回 `2005`，避免额外暴露封禁状态）、`1001`（参数为空或超长）。

## 2.4 当前登录用户

`GET /auth/me` ｜ 需要登录

返回当前账号信息，可用于刷新页面后恢复登录态。

**响应 `data`**：字段结构同 2.2（`id / username / nickname / role / createdAt`）；`role` 是当前账号的实际角色，管理员调用时为 `ADMIN`。

**常见错误**：`1002`（未登录或登录已失效）→ 清本地令牌并跳转登录。

## 2.5 发送找回密码验证码

`POST /auth/password-reset-codes` ｜ 公开

忘记密码时，先给账号邮箱发一个 6 位验证码。**只有已注册且未被封禁的邮箱才会收到**。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `email` | string | 是 | 注册时用的邮箱，≤128 字符；服务端会去掉首尾空格并转成小写 |

```json
{ "email": "alice@example.com" }
```

**响应 `data`**：同 2.1（`expiresInSeconds` / `resendAfterSeconds`），前端倒计时逻辑可以直接复用。

**常见错误**：`1000`（部署关闭了邮箱验证，接口不可用）、`1001`（邮箱为空或格式不对）、`2001`（该邮箱尚未注册 → 引导去注册）、`2004`（账号已被封禁 → 提示联系管理员）、`2008`（发送过于频繁）、`2009`（邮件发送失败）。

> 这个接口**会明确告知邮箱是否已注册**（与 `POST /auth/register` 的 `2003` 一致，属于产品选择）。
>
> 限流与 2.1 共用同一份配额：同一邮箱**每小时最多 5 封**、两次之间至少间隔 **60 秒**，注册码与找回码**合并计数**——所以不要在前端把两个按钮当成互不相干的入口反复点。

## 2.6 通过验证码重置密码

`POST /auth/password-resets` ｜ 公开

用 2.5 收到的验证码设置新密码。**旧密码立即失效，之前签发的所有 JWT 也立即失效**；成功后需要重新登录。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `email` | string | 是 | 注册邮箱 |
| `emailCode` | string | 是 | 2.5 发送到该邮箱的 6 位验证码 |
| `newPassword` | string | 是 | 8-64 位；规则与注册密码一致 |

```json
{ "email": "alice@example.com", "emailCode": "482915", "newPassword": "newpassword456" }
```

**响应 `data`**：`null`；成功后直接跳登录页，用新密码登录。

**常见错误**：

| code | 含义 | 前端处理 |
| --- | --- | --- |
| `1000` | 部署关闭了邮箱验证，无法通过邮箱找回密码 | 提示联系管理员或使用其他改密方式 |
| `1001` | 字段不合法（新密码太短、`emailCode` 缺失/空字符串/非 6 位数字等） | 按 `message` 提示 |
| `2001` / `2004` | 邮箱未注册 / 账号被封禁 | 引导注册 / 提示联系管理员 |
| `2007` | 验证码错误、已过期、已被使用、输错次数超限，或**拿了注册验证码来重置** | 提示 `message` 并让用户回 2.5 重新获取 |

> 两条容易踩的规则：
> 1. **码与用途绑定**：注册验证码不能用来重置密码（反之亦然）。
> 2. **只有最新一封邮件的码有效**：重新获取一次，之前的码立即作废；同一个码也只能成功使用一次。

## 2.7 登出所有设备

`POST /auth/logout-all` ｜ 需要登录

让当前账号之前签发的所有 JWT 立即失效，并为**当前设备**返回一个新的 token。其他设备需要重新登录。

**请求体**：无。

**响应 `data`**：结构同 2.3 的登录响应：

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "tokenType": "Bearer",
  "expiresIn": 604800,
  "user": {
    "id": 12, "username": "alice", "nickname": "Alice",
    "role": "USER", "createdAt": "2026-10-30T11:18:05"
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `token` | 新的访问令牌，请立即替换本地保存的旧 token |
| `tokenType` | 固定为 `Bearer` |
| `expiresIn` | 有效期（秒），默认 604800 秒（7 天） |
| `user` | 当前用户信息 |

**常见错误**：`1002`（未登录或登录已失效；调用本接口时使用的 token 也必须有效）。

> 这个接口不会返回“已登出设备数量”。调用成功后，除响应里的新 token 外，之前的所有 token 都无法再使用。
