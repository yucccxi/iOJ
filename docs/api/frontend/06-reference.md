# 参考与排障

本文汇总前端最容易踩的字段、空值、状态和现象，读者为前端与外部调用方。完整枚举与错误码见 [API 通用约定](../README.md)，页面与接口对照见 [前端 API 索引](README.md#3-页面与接口对照)。

> 返回目录：[前端 API 索引](README.md)

## 1. 可能为 null 的字段

| 位置 | 字段 | 说明 |
| --- | --- | --- |
| 题目详情 | `inputFormat`、`outputFormat`、`hint` | 可能未填写，返回 `null` |
| 题目详情 | `samples[].explanation` | 可能未填写，返回 `null` |
| 题目详情 / 统一题库 | `rating` | 未评分时返回 `-1`，不是 `null` |
| 题目详情 / 统一题库 | `tags`、`samples` | 空数组 `[]`，不会是 `null` |
| 统一题库 | `code` | 本地题恒为 `null`；外部题无法推导题号时也可能为 `null` |
| 统一题库 | `time` | 本地题恒为 `null`；外部题 clist 未提供时间时也可能为 `null` |
| 统一题库 | `url` | 本地题恒为 `null`；外部题非空 |
| 统一题库 | `authorId` / `authorNickname` | 外部题恒为 `null`；本地题非空 |
| 提交详情 | `code` | 无权限查看时为 `null` |
| 提交详情 | `compileMessage` | 只有编译错误时有值 |
| 提交详情 | `judgeMessage` | `SYSTEM_ERROR`、判题器准备/运行失败时可能有值 |
| 提交详情 | `timeUsedMs` | 尚未开始评测、编译错误、系统错误、判题器准备失败时可能为 `null` |
| 提交详情 | `memoryUsedKb` | 该次评测未提供内存统计时为 `null` |
| 提交详情 | `judgedAt` | 尚未评测完成时为 `null` |
| 提交详情 | `cases` | 无权限、编译错误、系统错误、判题器准备失败时为 `[]` |
| 提交详情 | `cases[].memoryUsedKb` | 该测试点没有内存统计时为 `null` |
| 提交详情 | `cases[].message` | 通过/答案错误时一般为 `null` |
| 列表 | `items` | 无数据或页码超出范围时为 `[]`，此时 `total` 可能不为 0 |
| 管理员判题节点 | `hostname`、`version`、`isolateVersion`、`lastHeartbeatAt` | Agent 未上报或刚注册时可能为 `null` |

> 数值字段为 `null` 时建议统一显示为 `-`，不要直接渲染 `null`。`rating` 是例外：接口已经归一化为 `-1`，前端可以直接展示“未评分”。

## 2. 状态与可见性补充

- `solved` 为 `false` 可能是未登录，也可能确实没通过；先判断登录态。
- `GET /submissions` 与 `/submissions/{id}` 不按题目可见性过滤；未发布题目的提交摘要可能被公开看到。不要据此判断题目已公开。
- `GET /problems/{id}` 对未发布题目返回 `403` / `3002`；这是“题目不可见/已下架”，不是“账号无权限”。
- `CHECKER_ERROR` 是题目自带判题器的问题，不是选手代码错误；应提示稍后重试或联系出题者。
- `SYSTEM_ERROR` 是评测环境问题；可在提示中建议稍后到提交列表重试。
- 管理员用户列表不返回邮箱和封禁状态；不要用 `role` 推断封禁状态。

## 3. 常见现象与处理

| 现象 | 原因 | 前端处理 |
| --- | --- | --- |
| 打开题目返回 `403` + `3002` | 题目未发布或已下架 | 提示“题目不可见或已下架”，不要显示“无权限” |
| 提交返回 `400` + `3003` | 题目还没有测试数据 | 提交按钮置灰，提示等待作者补充 |
| 上传题目后在题库看不到 | 部署关闭了自动发布，题目进入 `PENDING_REVIEW` | 读响应里的 `status`；到“我的题目”查看状态 |
| 上传后立刻能看到、没有“待审核” | 部署开启了自动发布 | 正常行为，不要写死“上传→待审核” |
| 编辑题目后部分内容变空 | `PUT /problems/{id}` 是整体替换 | 表单提交时带上所有字段（含 `tagIds`、样例） |
| 上传题目返回 `1000` 且提示“标签不存在” | 标签是管理员维护的字典 | 先拉 `GET /meta/tags`，用返回的 `id` 组成 `tagIds` |
| 提交后一直 `PENDING` / `JUDGING` | 评测较慢、排队或 Agent 离线 | 轮询 30-60 秒后提示到“我的提交”查看；必要时检查管理后台节点 |
| 测试数据编号不连续 | 删除中间数据后不重排 | 正常现象，按编号展示 |
| 提交显示 `CHECKER_ERROR` | 判题器编译失败/超时/崩溃 | 提示“评测机处理中，请稍后重试”，并通知出题者 |
| 怀疑编辑题目把判题器弄丢了 | `PUT /problems/{id}` 不会改判题器 | 用 `GET /problems/{id}/checker` 复核；判题器使用独立表单 |
| 注册返回 `400` + `2007` | 验证码错误/过期/已使用/输错超限 | 提示 `message`，恢复“重新获取验证码”按钮 |
| 注册返回 `429` + `2008` | 同邮箱 60 秒内重复点击或超出小时上限 | 按 `resendAfterSeconds` 倒计时 |
| 点“获取验证码”返回 `503` + `2009` | SMTP 发送失败 | 提示稍后重试并通知维护者，不要提示“邮箱错误” |
| 找回密码返回 `404` + `2001` | 该邮箱没有账号 | 提示“该邮箱尚未注册”，给注册入口 |
| 重置密码返回 `400` + `2007` | 验证码错误/过期/已使用/用了注册码 | 提示 `message`，重新获取找回密码验证码 |
| 登录/发码返回 `400` + `2010` | 图形验证码错误、过期、已使用、超限或 purpose 不匹配 | 重新获取图形验证码 |
| 获取图形验证码返回 `429` + `1006` | 单 IP 申请过于频繁 | 稍后重试，不要持续请求 |
| 重置成功后刷新页面仍显示登录 | 浏览器还带着旧 token | 清除本地 token，用新密码重新登录 |
| token 过期后页面像“未登录” | 公开接口不会因 token 失效报错 | 请求 `/auth/me` 判断登录态，失败则引导登录 |
| 管理页看不到谁被封禁 | 用户列表不含封禁状态 | 与后端约定扩展字段后再实现 |
| 上传较大的测试数据失败 | 单条超限、请求体超限或 MySQL packet 限制 | 按错误码区分：`1000` 调大测试点上限；`413` 调大 Nginx；`500` 查 `max_allowed_packet` |

## 4. 枚举补充

题目状态：

| 状态 | 含义 | 公开可见 |
| --- | --- | --- |
| `DRAFT` | 草稿，当前版本不会产生 | 否 |
| `PENDING_REVIEW` | 待审核 | 否 |
| `PUBLISHED` | 已发布 | 是 |
| `HIDDEN` | 已下架 | 否 |

评测状态与中文文案见 [提交与评测 §4](04-submissions.md#4-评测状态)。
