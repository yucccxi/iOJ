# API 通用约定

本文说明 iOJ HTTP API 的地址、认证、统一响应、分页、时间格式、错误码、权限可见性和版本策略，是前端接口与内部判题接口共用的约定。具体接口按调用方拆分：

- 前端 / 外部调用方：[前端 API 索引](frontend/README.md)。
- 判题 Agent（内部）：[内部判题 API 索引](judge/README.md)。

> 返回目录：[文档总索引](../README.md)

## 1. 地址与请求格式

| 项 | 说明 |
| --- | --- |
| 前端 Base URL | `http://<host>:8080/api/v1`；部署 profile 默认端口为 `8082` |
| 内部判题 Base URL | `http://<host>:8080/internal/judge`；不经过 `/api/v1` |
| 请求格式 | 有请求体时使用 `Content-Type: application/json`，UTF-8 |
| 字段命名 | JSON 使用 camelCase，大小写敏感；请求体里多传的字段会被忽略 |
| 成功 HTTP 状态 | 所有业务成功都返回 `200`，包括创建与删除；不使用 `201` / `204` |
| 时间 | 本地时间字符串，无时区后缀，例如 `2026-10-30T11:18:05`；可能带小数秒，按字符串或日期库解析；服务端默认使用 `Asia/Shanghai` |
| 枚举 | 大写英文，例如 `EASY`、`PUBLISHED`、`WRONG_ANSWER` |
| 数值单位 | 时间 `ms`，内存 `KB` 或 `MB`，字节数按 UTF-8 计算 |

## 2. 认证

### 2.1 用户与管理员

除标注“公开”的接口外，都需要登录后拿到的 JWT：

```http
Authorization: Bearer <token>
```

- 令牌由 `POST /api/v1/auth/login` 返回，默认有效期 7 天（`604800` 秒），没有 refresh token。
- 服务端无 session；每次请求都会重新校验账号状态、角色和令牌版本。
- 修改密码、重置密码或调用 `POST /api/v1/auth/logout-all` 会使该账号之前签发的所有 JWT 立即失效。
- 管理员修改角色或封禁用户后，对方下一次请求立即按新角色/状态处理；封禁后已有 token 也会被拒绝。
- 公开接口携带无效 token 时按未登录处理，不会返回 `401`；需要登录的接口返回 `401` + `1002`。

### 2.2 判题 Agent

内部判题接口使用管理员创建的 API key，不使用用户 JWT：

```http
Authorization: Bearer <judge-key>
```

- key 的明文只在创建响应中出现一次；服务端只保存 SHA-256 哈希和前 12 位前缀。
- key 可以设置过期时间，也可以被禁用或删除；失效后 claim/result 返回 `401`。
- 用户 JWT 不能访问 `/internal/judge/**`，判题 key 也不能访问 `/api/v1/**`；两类凭据不得混用。
- 一个 key 只对应一个判题节点。

> **内部接口**：`/internal/judge/**` 仅供判题 Agent 使用，不得暴露到公网或写进公开调用示例。部署时用内网地址或限制来源 IP。

## 3. 统一响应

所有接口返回同一个信封：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | integer | `0` 成功；非 `0` 为业务错误码 |
| `message` | string | 成功固定 `ok`；失败为可直接展示给用户的提示 |
| `data` | object / array / null | 业务数据；无返回值的接口为 `null` |

判断成功与否只看 `code == 0`，不要只看 HTTP 状态码。错误示例：

```json
{
  "code": 1001,
  "message": "password: 密码长度需为 8-64 位; email: 邮箱格式不正确",
  "data": null
}
```

约定：

- 值为 `null` 的字段仍会出现在 JSON 中；判断“有没有值”请用 `!= null`。
- 空列表返回 `[]`，空对象返回 `{}`，不会用 `null` 代替空集合。
- 参数校验失败时 `message` 会拼接多个字段原因，格式为 `字段: 原因; 字段: 原因`。
- 服务端不会返回堆栈、SQL 或内部类名。

## 4. 分页

列表接口统一使用 `page` + `size`：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `page` | 1 | 页码，从 1 开始；小于 1 会被纠正为 1 |
| `size` | 20 | 每页条数；小于 1 会被纠正为 1，大于 100 会被纠正为 100 |

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "size": 20
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `items` | array | 当前页数据；没有数据或页码超出范围时为 `[]` |
| `total` | integer | 满足筛选条件的总条数，不是总页数 |
| `page` / `size` | integer | 实际生效的页码和条数 |

列表接口的排序字段和方向在各接口文档中说明；没有特别说明时按 id 倒序（最新的在前）。

## 5. 错误码

### 5.1 通用与安全

| code | HTTP | 含义 | 调用方处理建议 |
| --- | --- | --- | --- |
| `0` | 200 | 成功 | — |
| `1000` | 400 / 405 / 415 | 请求参数错误 | 检查参数名、类型、枚举值；`405` 是方法不对，`415` 是 `Content-Type` 不是 JSON |
| `1001` | 400 | 参数校验失败 | 按 `message` 提示用户 |
| `1002` | 401 | 未登录或登录已失效 | 清除本地 token，跳转登录 |
| `1003` | 403 | 没有权限 | 提示无权限；后台页面需校验角色 |
| `1004` | 404 | 资源不存在 | 跳 404 页或刷新列表 |
| `1005` | 409 | 资源已存在或状态冲突 | 提示更换信息或稍后重试 |
| `1006` | 429 | 请求过于频繁 | 稍后重试；图形验证码签发接口会使用 |
| `1500` | 500 | 服务器内部错误 | 提示稍后重试，并记录请求 id/时间便于排查 |

### 5.2 账号

| code | HTTP | 含义 |
| --- | --- | --- |
| `2001` | 404 | 用户不存在 |
| `2002` | 409 | 用户名已被占用 |
| `2003` | 409 | 邮箱已被注册 |
| `2004` | 403 | 账号已被禁用 |
| `2005` | 401 | 用户名或密码错误 |
| `2006` | 400 | 原密码不正确 |
| `2007` | 400 | 邮箱验证码错误、已过期、已使用或尝试次数超限 |
| `2008` | 429 | 验证码发送过于频繁 |
| `2009` | 503 | 邮件发送失败 |
| `2010` | 400 | 图形验证码错误、已过期、已使用、次数超限或用途不匹配 |

### 5.3 题目与提交

| code | HTTP | 含义 |
| --- | --- | --- |
| `3001` | 404 | 题目不存在 |
| `3002` | 403 | 题目尚未发布或已下架 |
| `3003` | 400 | 题目至少需要一个测试点 |
| `3004` | 404 | 测试点不存在或不属于该题 |
| `3005` | 400 | 测试点数量超出上限 |
| `4001` | 404 | 提交记录不存在 |
| `4002` | 400 | 语言不受支持 |
| `4003` | 400 | 代码长度超出限制 |

> 同一个业务错误可能由不同 HTTP 状态承载，例如 `1000` 可能配 `400`、`405` 或 `415`。前端应以 `code` 为准，HTTP 状态只用于网络层判断。

## 6. 枚举速查

| 枚举 | 取值 | 使用位置 |
| --- | --- | --- |
| 用户角色 | `USER` / `ADMIN` | 用户资料、管理后台、权限判断 |
| 用户状态 | `ACTIVE` / `BANNED` | 管理后台封禁/解封 |
| 难度 | `EASY` / `MEDIUM` / `HARD` / `UNKNOWN` | 题目、统一题库；本地题不能创建 `UNKNOWN` |
| 题目状态 | `DRAFT` / `PENDING_REVIEW` / `PUBLISHED` / `HIDDEN` | 我的题目、审核列表、题目详情 |
| 语言 | `JAVA` / `CPP` / `C` / `PYTHON3` | 提交、语言列表 |
| 图形验证码用途 | `LOGIN` / `EMAIL_SENDING` | `POST /api/v1/captcha` 的 `purpose` |
| 邮箱验证码用途 | `REGISTER` / `RESET_PASSWORD` | 服务端内部；注册码与重置码不能混用 |
| 标签匹配模式 | `ANY` / `ALL` | 统一题库的 `tagMatch` |
| 排序方向 | `ASC` / `DESC` | 统一题库的 `order` |
| 统一题库排序 | `DEFAULT` / `RATING` / `ACCEPTED` / `SUBMISSIONS` / `ACCEPTANCE_RATE` | 统一题库的 `sort` |
| 判题状态 | `PENDING` / `JUDGING` / `ACCEPTED` / `WRONG_ANSWER` / `TIME_LIMIT_EXCEEDED` / `MEMORY_LIMIT_EXCEEDED` / `OUTPUT_LIMIT_EXCEEDED` / `RUNTIME_ERROR` / `COMPILATION_ERROR` / `CHECKER_ERROR` / `SYSTEM_ERROR` | 提交列表/详情、逐测试点结果 |

题目状态含义：

| 状态 | 含义 | 公开可见 | 说明 |
| --- | --- | --- | --- |
| `DRAFT` | 草稿 | 否 | 当前版本不会产生，保留给将来 |
| `PENDING_REVIEW` | 待审核 | 否 | 关闭自动发布时，普通用户上传后的初始状态 |
| `PUBLISHED` | 已发布 | 是 | 自动发布或管理员审核通过 |
| `HIDDEN` | 已下架 | 否 | 管理员驳回或下架 |

## 7. 可见性与权限

角色只有 `USER` 和 `ADMIN`；资源级权限在服务端按“作者 / 管理员 / 本人”判断。

| 操作 | 匿名 | 登录用户 | 题目作者 | 管理员 |
| --- | --- | --- | --- | --- |
| 注册、登录、找回密码、获取图形验证码 | 可以 | 可以 | 可以 | 可以 |
| 浏览已发布题目、统一题库、参考数据 | 可以 | 可以 | 可以 | 可以 |
| 上传题目 | 不可以 | 可以 | 可以 | 可以 |
| 编辑 / 删除题目 | 不可以 | 不可以 | 可以 | 可以 |
| 提交代码 | 不可以 | 可以 | 可以 | 可以 |
| 查看提交列表 / 公开详情 | 可以（不含代码） | 可以 | 可以 | 可以 |
| 查看他人提交的代码、编译信息、逐点结果 | 不可以 | 不可以 | 自己题目的提交 | 可以 |
| 查看隐藏测试点 / 判题器源码 | 不可以 | 不可以 | 可以 | 可以 |
| 查看未发布题目详情 | 不可以 | 不可以 | 可以 | 可以 |
| 题目审核、用户管理、标签/scope/判题机管理 | 不可以 | 不可以 | 不可以 | 可以 |

实现位置：

- URL 级：`SecurityConfig` 的公开白名单和 `/api/v1/admin/**` 角色规则。
- 方法级：管理员 Controller 上的 `@PreAuthorize("hasRole('ADMIN')")`。
- 资源级：`ProblemService#assertCanManage`、`SubmissionService#canSeePrivate`、`TestcaseService`。

> `GET /api/v1/submissions` 不按题目可见性过滤：未发布题目的提交摘要也可能被公开列出。未发布题目的“不可见”只约束题面详情；如果业务要求更严格的隔离，需要在服务端补过滤，前端不要依赖列表为空来判断题目未发布。

## 8. 跨域、限流与幂等

### 8.1 CORS

- 默认只允许 `http://localhost:5173`；通过 `IOJ_CORS_ORIGINS` 配置，多个来源用逗号分隔。
- 允许方法：`GET` / `POST` / `PUT` / `PATCH` / `DELETE` / `OPTIONS`；请求头不限。
- 带 `Authorization` 的跨域请求会先发 `OPTIONS` 预检，预检不会返回 `1002`。
- 前后端同域部署时通常不会触发 CORS；分域部署必须把前端来源加入配置。

### 8.2 限流

公开 API 没有全局限流；以下接口有专门的频率限制：

| 接口 | 限制 | 错误 |
| --- | --- | --- |
| `POST /api/v1/captcha` | 单 IP 每分钟 / 每小时签发次数 | `429` + `1006` |
| `POST /api/v1/auth/email-codes` | 同邮箱重发冷却、每小时上限 | `429` + `2008` |
| `POST /api/v1/auth/password-reset-codes` | 同上，与注册验证码共用配额 | `429` + `2008` |

提交代码目前没有用户级频率限制，前端应做防重复点击。

### 8.3 幂等

- 普通创建接口不幂等：重复提交会创建多条记录（例如重复提交代码）。
- 判题结果回报按 `claimToken` 幂等：同一 token 重复回报成功但不重复写；旧 token 返回 `409`。
- 删除接口重复调用可能返回 `404`，调用方应把“已不存在”视为目标状态。

## 9. 版本策略

- 前端接口使用 `/api/v1` 前缀；新增可选字段视为兼容变更，删除字段、改变字段含义或枚举取值视为不兼容变更。
- 不兼容变更必须新增版本前缀或提供迁移期；当前没有废弃接口清单。
- 内部判题协议使用独立版本号（当前 `2`），详见 [内部判题 API](judge/README.md)。协议版本不兼容时 Agent 拒绝启动，而不是带着不匹配的字段继续运行。
